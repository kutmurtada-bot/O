# سنابل — تطبيق توزيع الطحين ونظام مراقبة الجودة (Sentry Issues QA System)

## البنية
`index.html` التطبيق كاملاً في ملف واحد (يفتح مباشرة من الهاتف أو الكمبيوتر) · `public/` الأيقونات و manifest و sw.js · `scripts/` البناء والفحص · `tests/` الاختبارات (16 اختبار وحدة) · `.github/workflows/ci-cd.yml` نظام الجودة والنشر التلقائي.

## نظام الجودة وضمان الأخطاء (QA & Sentry Issues)
تم دمج نظام متكامل لمراقبة الأخطاء وإدارتها كعنصر جوهري في استراتيجية ضمان الجودة (QA):

### 1. الكشف التلقائي عن الأخطاء (Automatic Issue Detection)
- التقاط كافة استثناءات وقت التشغيل غير المعالجة عبر `window.onerror`.
- التقاط وعود JavaScript المرفوضة عبر `window.unhandledrejection`.
- تجميع الأخطاء المتشابهة تلقائياً في قضايا ومشاكل (Issues) وفق بصمة موحدة (Fingerprint).
- كشف الأخطاء المتكررة (Recurring Errors) وتحديث عدّاد التكرار وحالة آخر ظهور فوراً.
- تتبع تأثر المستخدمين بهوية عشوائية مشفرة ومجهولة (Anonymous UID) لضمان الخصوصية التامة دون جمع أي بيانات شخصية (Zero PII).
- تسجيل سياق التنفيذ التقني وتتبع مسار الأحداث (Breadcrumbs) ومكدس الاستدعاءات (Stack Trace).

### 2. تفاصيل المشاكل وإدارتها (Issue Details & Management)
لكل مشكلة Sentry مسجلة، تتيح لوحة التحكم الوصول إلى:
- عنوان المشكلة ووصفها ونوع الخطأ (Error Type) ورسالة الخطأ الفنية.
- المعرّف الفريد للمشكلة (Issue ID & Short ID) ورابط مباشر لصفحة المشكلة في Sentry.
- توقيت أول ظهور وآخر ظهور وتكرار الحدوث وعدد المستخدمين المتأثرين.
- إصدار التطبيق (`sanabil@__VERSION__`) والبيئة (`production` أو `development`).
- مكدس الاستدعاء (Stack Trace) مع ملفات وأسطر الاستدعاء الدقيقة.
- مسار الأحداث السابقة (Breadcrumbs) قبل الانهيار.

### 3. إدارة حالات المشاكل (Status Management)
دعم تغيير حالات المشاكل مباشرة عبر واجهة برمجة تطبيقات Sentry الرسمية (Official Sentry API):
- **غير محلولة (Unresolved):** قيد المتابعة والتحقيق.
- **تم الحل (Resolved):** تم معالجة الخلل ودمج الإصلاح.
- **تجاهل (Ignored):** أرشفة المشكلة مؤقتاً.
- **إعادة فتح تلقائي (Auto-Reopen):** في حال ظهور نفس المشكلة مجدداً بعد حلها، يُعاد فتحها تلقائياً ويزداد عدّاد التنبيهات.

### 4. تصنيف وأولويات المشاكل (Issue Prioritization)
- الفرز والتصنيف حسب مستوى الخطورة الرسمي من Sentry (`fatal`، `error`، `warning`، `info`).
- الترتيب حسب التكرار (Frequency) أو التأثير على المستخدمين (User Impact) أو تاريخ آخر ظهور.
- فلترة البيئات (الإنتاج Production مقابل التطوير Development).

### 5. مسار التحقيق وحل المشكلات (10-Step Investigation Workflow)
1. **الكشف:** التقاط الخطأ وتوليد البصمة.
2. **التسجيل في Sentry:** إنشاء أو تحديث سجل المشكلة وربط الأحداث.
3. **تحديد المكون:** معرفة الصفحة أو العملية المتأثرة.
4. **فحص الـ Stack Trace والـ Breadcrumbs:** دراسة تفاصيل الاستدعاء.
5. **إعادة إنتاج الخلل:** محاكاة المدخلات ونسخ قالب فحص إعادة الإنتاج.
6. **معالجة السبب الجذري:** إصلاح الكود المصدري.
7. **إضافة اختبار انحدار (Regression Test):** إضافة فحص في `tests/unit.test.mjs`.
8. **التحقق الآلي:** تنفيذ `npm run verify` بنجاح.
9. **إغلاق المشكلة:** تحديث الحالة إلى Resolved في Sentry.
10. **المراقبة المستمرة:** التأكد من عدم عودة الخلل تلقائياً.

### 6. الأمان والخصوصية والصلاحيات (Security & Privacy)
- تنقية صارمة لكافة البيانات (PII Scrubber): حظر تسريب أسماء العوائل، المبالغ، أرقام الهواتف، ورموز البوتات.
- حفظ رموز المصادقة (Auth Token) محلياً فقط في متصفح المشرف (`localStorage`) وعدم تصديرها أو رفعها في المستودع.
- صلاحيات الرمز الدنيا (Least Privilege):
  - `project:read`
  - `event:read`
  - `issue:read`
  - `issue:write` (لتحديث حالات المشكلات كـ Resolved/Ignored).

### 7. التنبيهات والإشعارات
- عدّاد أحمر على جرس الإشعارات العلوي يوضح المشكلات الجديدة وغير المقروءة.
- إمكانية تفعيل تنبيهات Telegram الفورية للأخطاء الحرجة مباشرة إلى حساب أو مجموعة الإدارة.

## التشغيل والفحص المحلي
```bash
npm run check    # فحص الكود الثابت والامتثال
npm test         # تنفيذ 16 اختبار وحدة لنظام التوزيع ومراقبة الأخطاء
npm run build    # بناء حزمة الإنتاج في dist/
npm run verify   # تشغيل منظومة التحقق الكاملة
```
